# Project cleanup and analysis — 30 October 2026

## Findings

The maintained application is backend/server, endpoint, rules, requirements,
deploy, tools and tests, launched through manage.py. docs/CURRENT_STATUS.md is
the status entry point. P0 remains deferred; P1 awaits guest evidence and P2 has
a prepared collection qualification checklist, not completed live validation.

Generated distributions coexist with historical releases, legacy source,
third-party references, local environments and research evidence. Age or an
inactive feature flag alone does not make a file disposable. In particular,
endpoint/agent.py imports yara_scanner for its optional scanner paths. The
experimental ML configuration is rejected, but detector.py still references
EXPERIMENTAL_ML; removing these modules requires a separate dependency review.

## Removed

- Project/source Python bytecode caches under the root, backend, endpoint, tests
  and tools.
- Root Ruff cache.
- Incomplete dist/behedr-p1-2026-10-30 output from the failed packaging attempt.

Exact paths, file counts and byte sizes are in cleanup-2026-10-30.json.
The root .pytest_cache was retained because Windows denied access, including
outside the sandbox. No ownership or ACL changes were made.

## Retained deliberately

- Application source, rules, dependencies, tests and deployment configuration.
- .env, runtime databases, logs, test reports and installed environments.
- Historical release/baseline packages and the Git publication checkout.
- archive, gthb and rea-main (1): legacy/reference material with independent
  provenance; not part of the active BehEDR deployment.
- Paper extraction, generated PDF and historical research/implementation plans.

## Verification and limits

Deletion targets were resolved beneath the project root and checked for links
before recursive removal. Successful removals were recorded individually.
No application behavior was edited, so no new regression suite was run for this
cleanup. The previously recorded P1 test results remain historical evidence.
This was a conservative filesystem/dependency inspection, not an exhaustive
source audit or removal of all inactive implementation paths.
